= Configure ARP/AI snapshot response policies and retention periods on ASA r2 storage systems
:icons: font
:imagesdir: ../media/

[.lead]
If Autonomous Ransomware Protection with Artificial Intelligence (ARP/AI) detects abnormal activity on one or more storage units on your ASA r2 system, it can automatically create an ARP snapshot to protect the data. Beginning with ONTAP 9.20.1, you can configure whether ARP/AI creates these snapshots by setting a snapshot response policy, independent of ARP/AI's ransomware detection and alerting, which always remains active. Depending on your storage capacity and business requirements, you might also want to increase or decrease the default ARP snapshot retention period.

== Configure a snapshot response policy for a storage unit

The snapshot response policy controls whether ARP/AI creates periodic snapshots, attack-triggered snapshots, or no snapshots at all for a storage unit.

[cols="1,3", options="header"]
|===
| Policy | Behavior
| Periodic and proactive snapshots (default) | ARP/AI creates snapshots at regular intervals and creates an additional snapshot when it detects an attack.
| Proactive snapshots only | ARP/AI creates a snapshot only when it detects an attack. No periodic snapshots are created.
| Alert only | ARP/AI generates alerts and event logs only. No ARP/AI snapshots are created.
|===

[CAUTION]
If you select the alert-only policy, ARP/AI does not create any snapshots. If a ransomware attack is confirmed, no ARP/AI snapshot is available for data recovery. Before selecting this policy, ensure you have adequate external data protection, such as scheduled snapshots or another backup solution.

[NOTE]
When you change the snapshot response policy, existing ARP/AI snapshots are not deleted immediately. They are deleted when their scheduled expiry time is reached.

.Steps
. In System Manager, select *Storage* and select the storage unit.
. Select *Security*.
. Under *Anti-ransomware*, select image:icon_kabob.gif[three vertical blue dots], and then select *Edit anti-ransomware settings*.
. Select the snapshot response policy to apply to the storage unit.
. Select *Save*.

== Configure a default snapshot response policy for a storage VM

You can set a default snapshot response policy at the storage VM level. New storage units created on the storage VM inherit this default; you can still override the policy for individual storage units.

.Steps
. In System Manager, select *Cluster > Storage VMs*.
. Select the storage VM.
. In the *Security* section, next to *Anti-ransomware*, select image:icon_kabob.gif[three vertical blue dots], and then select *Edit anti-ransomware settings*.
. Select the default snapshot response policy to apply to new storage units created on the storage VM.
. Select *Save*.

== Modify ARP/AI snapshot retention periods

If the snapshot response policy for a storage unit creates periodic or attack-triggered ARP snapshots, the default retention period for those snapshots varies depending on the action you take in response to the abnormal activity.

[cols="2,2", options="header"]
|===
| If you take this action... | ARP snapshots are retained by default for...
| Mark as false positive | 12 hours
| Mark as potential ransomware attack | 7 days
| Do not take immediate action | 10 days
|===

You can modify the default retention periods by using the ONTAP command line interface (CLI). See https://docs.netapp.com/us-en/ontap/anti-ransomware/modify-automatic-snapshot-options-task.html[Modify options for ONTAP automatic snapshots] for steps to change the default retention period.
